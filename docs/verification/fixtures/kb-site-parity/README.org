#+title: Parity fixture bundle (kb-site-parity, §4.1)

A public, synthetic fixture for the knowledge-base site parity specification
(docs/verification/kb-site-parity.md in MAE). Every page is invented for this purpose: nothing
here comes from any real or private knowledge base. Build both the reference engine and the
candidate engine from =bundle/=, =data/= and =site.yaml=, then run the parity acceptance suite
against both.

* Layout

- =bundle/= :: the org files: the only content input.
- =data/= :: build-time data: route history, version records.
- =site.yaml= :: the site configuration both engines take (locale, base path, KB identifier,
  palette, slots, hidden namespaces, descending folders, the what's-new node).
- =negative/= :: one directory per build failure of §3.17, each with =expected.json= (exit code,
  and the log line or the absence it must produce).

* Data formats

The fixture defines its own neutral contracts; each engine's build adapter translates them into
whatever that engine reads, outside this repository.

- Document state: the file-level property =:STATE:= with =draft=, =in-review=, =approved=,
  =in-force=, =superseded= or =withdrawn= (exact text; anything else is an invalid state).
- Last updated: =:UPDATED: YYYY-MM-DD= (a day that exists). Every page but =status/malformed-date.org=
  has a distinct valid date, so "most recent" (P-75) has one answer.
- Route history (=data/route-history.json=): ={"format": "route-history/1", "routes": {"<old
  path>.org": "<ID of the last page that had it>"}}=.
- Version data (=data/version/=): =version.json= ={"schema": 1, "version": "vA.B.C", "commit",
  "date"}= and =changes.json= ={"schema": 1, "versions": [{"version", "date", "sections": [{"type",
  "entries": [{"text", "scope", "commit", "breaking"}]}]}]}=.
- Palette: =neutral=.

Highlighting follows each engine's declared language list: a block is expected highlighted when its
language is on the engine's list and plain otherwise. =code.org= covers twenty common names; the
typo language and the undeclared block are plain for every engine.

* Not covered here

- CR-LF inside a code block (P-107): MAE's seed planner refuses CR-LF files, so the bundle keeps LF
  only; the suite injects a CR-LF page into its own temporary copy of the bundle, never into this
  repository.
- What needs the build environment rather than content (P-142 symbolic link, P-143 non-empty
  output, P-145 a broken extension, P-146 an unknown warning, P-149 the sandbox, P-166 a page in
  the engine's tag namespace): the negative
  fixtures describe them, and the suite's runner creates them at run time.
- Where the reference engine's exit differs from the requirement, the case's =expected.json= says so
  under =reference= (=exit= =null=: the condition cannot be forced on the reference). The
  requirement's =exit= stays the one a conforming engine must give.
