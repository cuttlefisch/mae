#+title: KB Authoring Workflow
#+filetags: :molecular-notes:workflow:devpractice:

Building out a molecular notes knowledge base follows a consistent compose sequence. Each step depends on the ones before it, and the sequence is designed specifically to avoid the failure mode where linking and synthesis get deferred to a "cleanup pass" that, in practice, never happens reliably — every step below that produces a link or a synthesis does so immediately, not on a later pass.

1. **Capture source material first, if there is any.** If the work draws on external reference material — a spec, a vendor doc, a meeting transcript, a citation — create the source note before writing anything else, holding the material close to verbatim with its origin recorded. Not every KB addition has a source behind it; skip this step for material that is the author's own established knowledge with nothing external to cite. See [[id:practice:source-preservation][source preservation]] for the source/atom split this step sets up.
2. **Distill atoms from the source, or write atoms directly.** For each distinct idea in the source material (or in the author's own knowledge, if there was no source step), write one atom note: a single claim, restated in the author's own words, scoped to the smallest independently useful unit. Do not write one atom that bundles several ideas because they came from the same source or the same train of thought — split them by claim, not by origin.
3. **Build cross-links as each atom is written, not deferred to a later pass.** The moment an atom is created, link it to every existing note it genuinely relates to — a sibling atom on an adjacent topic, the hub for its topic area, a source note it was drawn from. This is the step most often skipped under time pressure, and skipping it is exactly how a KB accumulates orphan notes: a deferred "I'll link everything up later" pass reliably does not happen, because by the time there is time for it, the context needed to know what should link to what has faded. Link while the connections are still obvious.
4. **Synthesize a molecule once enough related atoms exist.** When a cluster of atoms starts to imply a judgment call, a workflow, or an insight that none of them states individually, write a molecule that connects them — linking to each constituent atom rather than restating its content, and adding only the connective reasoning that is new. Do not force a molecule prematurely out of one or two atoms that do not yet have enough to synthesize; wait until the connection is real.
5. **Add or update a hub once a topic has enough atoms and molecules to need a map.** A topic with two or three notes does not need a hub; a reader can hold that many in mind unaided. Once a topic accumulates enough notes that a newcomer would otherwise have to guess where to start, create a hub (or extend an existing one) that lists and briefly orients the reader to each note under that topic, grouped usefully rather than alphabetically.

Follow the sequence in order for new material, but treat it as cyclical for an established KB: a new atom added to an existing topic still triggers step 3 immediately, and may push an existing hub (step 5) or an existing molecule (step 4) to be updated rather than created fresh. The discipline that makes this workflow actually work is doing steps 3 through 5 inline as the triggering condition is met, rather than batching them — see [[id:practice:molecular-notes-overview][the molecular notes overview]] for why the resulting graph structure is worth this discipline, and [[id:practice:kb-audit-checklist][the KB audit checklist]] for the review pass that catches anything this workflow still missed before treating an addition as finished.
