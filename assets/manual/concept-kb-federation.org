#+title: KB Federation
#+filetags: :kb:federation:org-roam:

KB *federation* lets you register external org directories as searchable knowledge base instances alongside MAE's built-in help.

** Architecture
#+begin_src
+---------------------------------------------+
|           MAE Knowledge Base                |
+---------------+-----------------------------+
|  Local KB     |  Federated Instances        |
|  (seed +      |  +---------+ +---------+   |
|   user help   |  |RoamNotes| | Work KB |   |
|   + AI)       |  | 2,500   | | 87      |   |
|  200+ nodes   |  | nodes   | | nodes   |   |
|               |  +---------+ +---------+   |
+---------------+-----------------------------+
         | search / get / graph
    +---------------------+
    |  :help  |  AI tools |
    |  SPC h  |  kb_*     |
    +---------------------+
#+end_src

** Design principle
*The org directory is READ-ONLY for the KB layer. SQLite is derived.*
Your org files remain the canonical source of truth. MAE reads them, builds an in-memory graph, and never writes to your org directory (except one sentinel file: ~eor-instance.org~).

** Registry
Stored at ~~/.config/mae/kb-registry.toml~. Each instance has:
- UUID (generated or read from sentinel file)
- Name (user-chosen display label)
- Org directory path
- Enabled flag
- Last import timestamp

** Sentinel file
When you register a directory, MAE creates ~eor-instance.org~ with the instance UUID. This file is safe to delete -- MAE recreates it on next registration. It marks the directory as a MAE KB instance.

** Link scheme
- ~eor:node-id~ -- local-first lookup (checks local KB, then instances).
- ~eor:uuid/node-id~ -- targeted lookup in a specific instance.

** Import pipeline
1. Recursive ~walkdir~ over the org directory.
2. Parse each ~.org~ file for ~:ID:~ properties (file-level + heading-level).
3. Files without ~:ID:~ are counted but skipped.
4. File-path links (images, attachments) are NOT treated as KB links.
5. Duplicate ~:ID:~ values are detected and reported.
6. Health metrics (orphans, broken links, namespaces) computed automatically.

** Source of truth: the three states
A KB is in exactly one of three states, and which one decides whether your ~.org~ files still
matter. See ADR-110.

- *Attached* -- the ~.org~ directory is authoritative and ingest overwrites the store.
- *Migrating* -- the store is authoritative and the ~.org~ files remain as a *stale archive*:
  nothing reads them, and MAE opens them read-only with a banner so an edit cannot be silently
  stranded.
- *Native* -- the store is authoritative and there are no files at all.

- ~:kb-detach <name>~ -- attached to migrating. The store becomes the truth.
- ~:kb-attach <name>~ -- migrating back to attached; ingest resumes and overwrites the store.
- ~:kb-retire-archive <name>~ -- migrating to native. A DRY RUN by default; add ~confirm~ to
  proceed. Refuses unless every ~.org~ file is genuinely represented in the store, and is
  all-or-nothing. Files are MOVED to ~~/.local/share/mae/retired/<kb>/<date>/~, never deleted, and
  MAE never touches git.
- ~:kb-new <name>~ -- create a native KB directly, with no org directory.

Also available as Scheme: ~(kb-detach NAME)~, ~(kb-attach NAME)~, ~(kb-new NAME)~,
~(kb-retire-archive NAME)~ for the dry run and ~(kb-retire-archive! NAME)~ to move the files.
Keybindings live under ~SPC n t~ (+truth).

** Commands
- ~:kb-register <name> <path>~ -- register and import.
- ~:kb-unregister <name>~ -- remove instance.
- ~:kb-reimport <name>~ -- refresh after editing org files.
- ~:kb-instances~ -- list registered instances.
- ~:kb-health~ -- health report (orphans, broken links, namespace counts).
